01 · Install

Full stack install guide

Each layer installs independently. Start with what solves a real problem today — most people begin with battery sensing or the dashboard, not everything at once.

Prerequisites

  • A Cerbo GX or other Venus OS device with network access and SSH enabled.
  • An MQTT broker reachable from both the GX and wherever dashboards run (Mosquitto works).
  • For battery sensing: an ESP32 and a JBD BMS battery within Bluetooth range.

Recommended order

  1. Broker up first. Install Mosquitto somewhere always-on. Every component assumes it can reach the broker.
  2. Sense. Flash the ESP32 BLE proxy (esphome-jbd-bms-mqtt) and verify BMS data lands in MQTT.
  3. Publish to D-Bus. Install dbus-mqtt-battery on the GX. The battery appears in the Venus UI immediately.
  4. Add PV/grid metering if you have Tasmota plugs or a CT sensor — same pattern.
  5. Dashboard. Drop inverter-dashboard-go onto the Cerbo; open its port from any browser.
  6. Control last. Only after metering is trustworthy, install inverter-control. Test grid-zero behavior with conservative limits first. EV charging setpoints follow the same governed write path.
  7. Then the extras: long-term metrics, desktop client, forecasting, observability.

Verifying each step

After every layer, check before moving on:

# On the Cerbo — does the service run?
svc -s /service/dbus-mqtt-battery

# On anything — did data reach MQTT?
mosquitto_sub -t 'victron/#' -v

If victron/# shows values but the Venus remote console doesn't show the device, check the D-Bus service name against the integration reference.

Uninstalling is safe. Every D-Bus service removes cleanly via PackageManager or by deleting its /opt/victronenergy/service-name directory and restarting — no persistent state outside its own log directory.
