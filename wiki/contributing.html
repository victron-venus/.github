05 · Contributing

Making your first change

Start with the target repository's contribution guide. Keep each pull request focused so reviewers can assess its behavior and validation.

The flow

  1. Fork the target repository — or branch within the org if you're a maintainer.
  2. Create a feature branch from the target repository's default branch. One concern per branch.
  3. Make the change with tests where applicable. Bug fixes come with a regression test.
  4. Commit with Conventional Commits: feat:, fix:, docs:, chore:, refactor:, test:.
  5. Open a pull request. Describe what changes and why; link issues. CI and CodeQL must pass before merge.
  6. Address review feedback. Signed commits may be required on protected branches.

Local checks before pushing

Read the target repository's CONTRIBUTING.md and use its documented local validation command. Toolchains, lint rules and test package names differ between projects. If a repository provides scripts/ci.sh, inspect that script and install its documented prerequisites before running it:

bash scripts/ci.sh

Where the contribution guide also requires pre-commit, run the checked-in configuration and review any automatic changes:

python3 -m pre_commit run --all-files

Report the exact checks run and any limitations in the pull request. Offline checks do not establish physical-device behavior; installation and hardware acceptance are separate steps. See the website contribution guide for this site's own validation requirements.

Approval gates for control code

Changes touching the write path — anything that ends up commanding an inverter or battery — get extra scrutiny by design:

  • New setpoints or policy rules must preserve the deployed controller's source-validity, limit and watchdog checks and verify D-Bus write acknowledgements. The archived governance project is not an installed gate.
  • Document the command's actual logging and verification path. Do not claim mandatory event-log coverage when that service is not deployed.
  • Default-off. Risky behavior ships disabled until configuration explicitly enables it.

Where to ask

  • Bug or feature? Open an issue on the repo using the issue templates — they route to the right maintainers.
  • Questions about Venus OS integration patterns start in integration-patterns discussions or the Victron community forum.
